# API Contract

> **Status: placeholder.** Only `GET /api/health` is implemented. Everything under
> "Planned endpoints" is illustrative and may change before implementation.

## Conventions

- **Base path:** `/api`
- **Media type:** `application/json; charset=utf-8`
- **Field naming:** `snake_case` (matches Python and keeps the mapping explicit)
- **Timestamps:** UTC ISO 8601 with a `Z` suffix
- **IDs:** opaque strings generated by the backend
- **Versioning:** not finalized. Introduce `/api/v1` or an explicit header before
  the first external consumer depends on the contract.
- **Errors:** RFC 9457 `application/problem+json` is the proposed shape; not
  implemented yet.
- **Pagination:** cursor-based pagination is proposed for list endpoints; not
  implemented yet.

## Implemented endpoints

### `GET /api/health`

Liveness and build metadata. No authentication, database read, or domain work.

**Response `200 OK`**

```json
{
  "status": "ok",
  "service": "Mission Autopsy API",
  "version": "0.1.0",
  "environment": "development"
}
```

| Field         | Type   | Description                                      |
| ------------- | ------ | ------------------------------------------------ |
| `status`      | string | Always `ok` when the process is serving requests |
| `service`     | string | Configured application name                      |
| `version`     | string | Core package version                             |
| `environment` | string | `development`, `test`, or `production`           |

Interactive documentation is available at `/docs`; the OpenAPI document is at
`/openapi.json`.

## Frontend integration

- All HTTP calls live in `frontend/src/api/client.ts`.
- Wire types live in `frontend/src/types/api.ts` and mirror this document.
- Components receive data as props; they do not call the API directly.
- In development, Vite proxies `/api` to `VITE_API_PROXY_TARGET`.
- In production, `VITE_API_BASE_URL` points at the deployed backend.

## Open questions

- Authentication and authorization model (none in the scaffold).
- Error envelope and validation-error mapping.
- Idempotency for `POST /api/investigations`.
- Long-running investigation execution: polling, server-sent events, or
  WebSockets.
- Pagination and filtering for investigations.
- Whether scenarios are read from YAML at request time or synchronized into
  SQLite at startup.
- API versioning strategy and deprecation policy.

## Change process

1. Update this document before changing a route or payload.
2. Update `backend/schemas/` and the route tests.
3. Update `frontend/src/types/api.ts` and the typed client.
4. Note breaking changes explicitly; do not silently change a field's meaning.
